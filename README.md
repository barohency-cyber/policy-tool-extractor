# policy-tool-extractor

> 面向公共事业管理研究的**政策文本分析小助手**：提取 → 信度 → 报告，一条链路跑完。

给一批政策文件，它做三件事：

1. **提取**——按 Rothwell & Zegveld 三分法（供给型 / 环境型 / 需求型）把文本编码成 14 个二级子工具，输出词次与篇次两种口径；
2. **信度**——两份独立编码可算 Krippendorff's α、Cohen's κ 与分歧清单，这是审稿人最先问的那张表；
3. **报告**——生成单文件 HTML，含图表、明细与方法学附录草稿，可直接改写成论文方法部分。

本仓库同时是一次研究的完整留档：**省级数字政府建设文件 + 编码手册 + 可复现脚本**。
目标不是做通用 NLP 工具，而是让「政策工具」这一测量过程**透明、可复核、可复现**。

---

## 一、研究主题

**省级数字政府建设中的政策工具选择：基于 4 份省级文件的文本分析。**

研究问题：

1. 省级数字政府建设文件偏好使用哪一类政策工具（供给型 / 环境型 / 需求型）？
2. 不同省份的工具组合是否存在系统性差异？
3. 现有中文文献在测量「数字政府政策工具」时采用什么框架与口径？

框架采用 Rothwell & Zegveld（1985）的三分法——供给型、环境型、需求型，
这是国内政策工具研究中使用最广的分类之一，便于与既有文献对话。

## 二、样本纳入与排除标准

### 纳入标准（同时满足）

1. **行政层级**：省级（省政府、省政府办公厅、省级主管部门正式发文）
2. **文件类型**：数字政府建设的实施方案、规划、实施意见等**部署类正式文件**
3. **内容体量**：正文 ≥ 3,000 字，且包含完整的任务/措施章节
4. **文本形态**：可复制文本（网页正文或文本型 PDF），非扫描件
5. **可获取性**：来源为政府域名（`*.gov.cn`）或省政府门户

### 排除标准（命中任一即排除）

| 排除情形 | 理由 |
|---|---|
| 市级、区县级文件 | 与「省级」研究范围不符，层级效应会混淆结论 |
| 政策解读、图解、答记者问、新闻稿 | 非正式发文，属二次加工文本 |
| 仅印发通知（无方案正文） | 正文缺失，无法编码 |
| 扫描件 / 图片型 PDF | 无文本层，需 OCR，会引入识别误差 |
| 正文 < 3,000 字的短通知 | 工具表述密度过低，编码噪音大 |
| 附件任务清单（非正文） | 清单是「做什么/谁做/何时」，不含政策工具表述 |

## 四、项目用途

1. **复现研究结果**：给定同一批文本与同一份词典，输出完全一致的政策工具频次表
2. **方法透明**：编码规则写在 `docs/coding_sheet.md`，词典写在 `code/extractor.py`，两者可逐条核对
3. **信度可算**：`reliability.py` 把「两人编码一致性」做成一条命令，不必再手算 α
4. **可扩展**：替换 `data/raw/` 中的文本即可分析其他政策领域，词典按需增删
5. **教学示例**：政策文本分析课程的完整流程样例（语料 → 编码 → 信度 → 报告）

## 六、快速开始

### 三步走

```bash
# 1. 提取（同时输出可人工复核的 0/1 编码矩阵）
python code/extractor.py --binary

# 2. 信度（可选：把 coding_matrix.csv 复制一份、由第二位编码员独立修订后）
python code/reliability.py --a output/coding_matrix.csv --b output/coding_matrix_b.csv

# 3. 报告
python code/report.py
```

### 产出文件

| 文件 | 内容 |
|---|---|
| `output/tool_counts_by_document.csv` | 每篇文本 × 每个子工具的命中次数，附字符数、总词次、命中子工具数 |
| `output/tool_summary.csv` | 子工具汇总：词次合计、篇次（出现文档数）、覆盖率 |
| `output/coding_matrix.csv` | 0/1 编码矩阵，可直接打印为人工编码表，或作为信度检验输入 |
| `output/reliability.csv` | 一致率、Krippendorff's α、Cohen's κ（需第二步） |
| `output/disagreements.csv` | 分歧单元明细，逐条复核用（需第二步） |
| `output/report.html` | 单文件报告：图表 + 明细 + 方法说明 |

## 七、两种统计口径

- **词次（frequency）**：关键词在全文出现的次数，反映**表述强度**
- **篇次（document presence）**：出现该子工具的文档数，反映**使用广度**

两种口径含义不同，不可混用。`tool_counts_by_document.csv` 给词次，
`tool_summary.csv` 同时给词次与篇次。

> 若论文中报告「X 类工具占 47.6%」，必须说明是按词次还是按篇次计算，
> 否则数字无法复现。

## 八、已知局限

1. **词典法的固有局限**：只识别显式表述，对「加大投入力度」这类隐含表达不敏感，会低估供给型工具
2. **关键词重叠**：「政务服务」与「政务服务平台」等同源词存在嵌套，词次会偏高，
   篇次不受影响，因此建议以篇次作为稳健性检验
3. **未做否定语境消解**：本版提取器不做「不得/禁止」等否定判断，
   需要时应在编码手册层面补充规则（见 `docs/coding_sheet.md` 边界规则）
4. **样本量小**：4 份文件仅够做描述性比较，不足以支撑统计推断
5. **文体差异**：规划、实施方案、实施意见三种文体的表述密度不同，跨文体比较需谨慎

## 九、数据来源与合规

- 全部政策文本来自政府公开网站，仅用于学术研究
- 抓取遵循来源站点的公开访问规则，请求间隔 3 秒
- 文献题录来自公开检索结果，未包含全文
